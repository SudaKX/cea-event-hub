# 首次启动引导管理员

开放注册无法产生第一个管理员，因此平台在启动时补上这个缺口。

## 触发条件

**用户表为空**时创建；只要表里已有任意一个用户就什么都不做。

触发器刻意不是"不存在名为 `admin` 的账号"。若用后者，管理员被有意删除之后，
一次普通重启就会悄悄复活一个**账号名已知**的特权账号——那条路径不该存在。

配合另一条约束（不能移除最后一个管理员），系统无法经由界面进入零管理员状态，
因此这个引导路径在真实环境中**只会在首次空库时执行一次**，此后永不触发。
它不是一条长期存在的后门。

## 配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `ADMIN_BOOTSTRAP_ENABLED` | `true` | 整体开关。关掉后空库启动也不会创建任何账号 |
| `ADMIN_USERNAME` | `admin` | 账号名。写入前会归一化（NFC + 去空白 + 小写） |
| `ADMIN_INITIAL_PASSWORD` | 空 | 初始口令。为空则生成高强度随机值 |

三者都可经环境变量或 `backend/.env` 覆盖。

## 口令的两种输出情形

这是本机制唯一需要权衡的地方：引导需要一个初始口令，而"随机且无人知晓"等于
系统不可用。因此分两种情形处理：

### 未设置 `ADMIN_INITIAL_PASSWORD`

生成 20 位随机口令，并在**创建该账号的那一次**以告警级别输出，附立即改密的提示：

```
======================================================================
  首次启动引导：已创建管理员账号
    用户名  : admin
    初始口令: WXvN4F7sfq4u2s+*E-Z_
  该口令只显示这一次，请立即登录并修改。
  若不想让口令出现在日志中，请设置 ADMIN_INITIAL_PASSWORD 后重建数据库。
======================================================================
```

重启后不会再输出该口令，任何接口也不会返回它。

### 已设置 `ADMIN_INITIAL_PASSWORD`

使用该值，且**启动输出中完全不出现口令**，只说明账号已创建：

```
首次启动引导：已创建管理员 'admin'（初始口令来自环境变量，未输出）。请登录后立即修改口令。
```

这是生产环境规避口令进入日志的**正式手段**。日志不是可靠渠道——它会被采集、
转发、长期保留，因此一条不落日志的路径比"随机口令 + 打印"更完整。

## 为什么不能移除注册保留名清单

引导账号的**账号名是可预测的**，它只有两道防线：登录限流与该账号的口令强度。

因此 `RESERVED_USERNAMES` 不可移除。它挡住的是两种情况：

1. 有人在引导之前抢先注册 `admin`，使平台失去管理入口；
2. 出现一个同名的普通账号，造成"谁是管理员"的混淆。

该清单在 `normalize_username` 之后比较，所以清单本身必须全部小写——否则大小写
差异会让保留名形同虚设。

## 口令丢失后的恢复

引导不会重跑，所以不能用"清空用户表"的办法找回——那会同时删掉所有活动与提交。

改用管理员签发重置令牌的路径（见 `docs/auth-contract.md`）。若连一个管理员都
没有（例如手工改库造成），需要直接操作数据库，或临时把 `ADMIN_BOOTSTRAP_ENABLED`
置为 `true` 后清空用户表重新引导（会丢失数据，仅限全新部署）。
