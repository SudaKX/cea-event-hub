# Spec Delta

## MODIFIED Requirements

### Requirement: 管理台外壳与访问控制
管理台 SHALL 提供活动、提交、用户与邀请四个入口的导航。未登录用户访问管理台 MUST 被引导至登录页，并在登录后回到原目标页面。非管理员用户 MUST 无法访问管理员专属页面。

**用户与邀请两个入口 MUST 仅对管理员可见**：它们管理的是账号与准入门槛，越权访问的影响面比活动与提交更大。

管理台 MUST 提供一条**回到公开站点**的出口（返回主页），且它 MUST 出现在导航区域的底部、MUST NOT 混在管理入口之间 —— 它不是又一个管理页面，读起来像的话会让人以为还有一处没去过。管理台是另一套版式（固定视口、没有站点页头），从书签直接进来时浏览器"后退"未必能一步回到首页，因此这个出口是必要的而非装饰。它与首页上那个"管理台"入口互成镜像。

个人中心页 MUST 为管理员提供直达邀请码管理的入口 —— 管理员在那里本来就没有"申请自己的码"这回事（那份额度属于普通用户），把入口指向管理台可以避免他以为功能缺失。

#### Scenario: 未登录被引导登录
- **WHEN** 未登录用户访问管理台路径
- **THEN** 被导航到登录页，并在登录成功后回到原先请求的页面

#### Scenario: 普通用户看不到管理员入口
- **WHEN** 普通用户登录后进入管理台
- **THEN** 用户管理入口不可见且直接访问被拒绝

#### Scenario: 会话失效时回到未登录态
- **WHEN** 管理台任意请求收到 401
- **THEN** 前端清除登录状态并引导至登录页

#### Scenario: 左下角有回主页的出口
- **WHEN** 进入管理台任意页面
- **THEN** 导航区域底部有一个指向平台首页的入口

#### Scenario: 邀请入口仅管理员可见
- **WHEN** 普通用户登录后进入管理台
- **THEN** 邀请入口不可见，且直接访问邀请码管理页面被拒绝

#### Scenario: 管理员在个人中心被引向邀请码管理
- **WHEN** 管理员打开个人中心
- **THEN** 邀请码卡片提供进入管理台邀请码管理的入口，而不是"申请自己的邀请码"
