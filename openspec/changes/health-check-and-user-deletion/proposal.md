# Proposal

## Why

**健康检查名不副实。** `/api/v1/health` 现在返回的是三个写死的字段，一次数据库都不碰 —— 库挂了、迁移没跑、连接池耗尽，它照样回 `{"status": "ok"}`。部署文档把它当作验收与 systemd 启动后的检查手段，一个永远说 ok 的检查等于没有检查。

**账号只能停用，不能移除。** 误注册、垃圾账号、测试残留都只能永久留在用户表里，而"停用"回答的是另一个问题（这个人不在了）。**而且现在直接删会出事**：`users.id` 是 rowid 别名、没有 `AUTOINCREMENT`，删掉最大的那个 id 之后，下一个注册的人会**拿回同一个 id** —— 于是他从数据角度"继承"了前者的提交与配额计数。这一点已实测复现（删 carol=3 → 新注册 dave 拿到 id 3 → 那条 `u:3` 的旧提交归了他）。同一个坑在本项目已经咬过一次：注册邮件的幂等键曾从占位行 id 派生，撞键后被 Resend 判为重放而永久发不出信。

## What Changes

- `/api/v1/health` 改为**真实检查**：做一次数据库往返，并在数据库不可达时返回 `503`；响应中给出迁移版本，使"代码已更新但迁移没跑"这种最常见的部署事故一眼可见。字段保持向后兼容，现有调用方（部署文档的验收命令）不必改。
- 新增 `DELETE /api/v1/admin/users/{id}`，成功返回 `204`。语义：
  - 该账号的**会话与一次性令牌一并消失**，无法再登录
  - 他**提交过的内容全部保留**，署名仍是 `u:{id}`，此后成为永久标识（id 不再被复用）
  - 他名下的配额计数行被清除，使活动的一致性检查不再报"计数与实际不符"
  - 该用户创建的活动与做过的审核**保留**，只是不再显示创建者/审核者
  - 守卫与停用同源：MUST NOT 删除最后一个**可用**管理员，MUST NOT 删除自己
  - 删除 MUST 被记录以便追溯
- **前置改动**：`users.id` 加 `AUTOINCREMENT`。这是上面那条"不继承"得以成立的前提，不是可选优化。
- 提交列表里的提交者，在账号已不存在时显示为 **「已删除用户 #7」**，而不是让管理员面对一个悬空的 `u:7`。**一次批量查询**解析整页，MUST NOT 每条一次。
- 用户管理界面增加删除入口，走应用自有的确认对话框（`danger`），文案说清"提交会保留、署名会变成编号、不可撤销"。

### 本期不做

- **不为根路径 `/health` 加端点。** 日志里那几百条 `GET /health → 404` 来自某个未知轮询者，它打错了路径；为它新增一个顶层路径会牵动 nginx 与前端保留前缀表，而它对部署没有任何用处。本变更只让**已有的** `/api/v1/health` 名副其实。
- **不做批量删除用户。** 删除是罕见且不可逆的动作，逐个点、逐个确认反而更合适。批量接口留给将来确有需要时再说。
- **不做匿名化/清空历史提交。** 保留提交是本变更的明确取向，与"停用不删提交"的既有约定一致。真要抹掉某个人的痕迹，属于另一类需求（合规），应当单独讨论。
- **不改 `pending_registrations.id`。** 它也同样是 rowid 别名，但没有任何东西从它的 id 派生（幂等键已改为从令牌摘要取），因此不构成风险；顺手改会多出一次无收益的表重建。
- **不验证 MySQL 的 `AUTO_INCREMENT` 重启行为。** 8.0 起该计数器持久化，更老的版本重启后会按 `max+1` 重算而可能复用 id；这是迁移到 MySQL 时的复核项，写进部署文档而不是在本变更里解决。

## Capabilities

### New Capabilities
- `service-health`: 健康检查应当反映服务是否**真的可用**（数据库可达、迁移就位），而不只是进程还活着。

### Modified Capabilities
- `user-administration`: 新增"账号删除"要求；并明确删除不得让后续注册的账号继承被删者的提交与配额。
- `submission-review`: 提交列表在提交者账号已不存在时的显示要求。

## Impact

- **后端**：`app/api/v1/health.py`（改为真实检查）、`app/api/v1/admin.py`（新增删除端点、提交者解析改为批量）、`app/services/auth.py`（删除、守卫、审计日志）、`app/repositories/users.py`（删除与计数清理）、`app/schemas/submissions.py`（提交者显示字段）
- **迁移**：一次 SQLite 表重建给 `users.id` 加 `AUTOINCREMENT` —— `users` 被五处外键引用，这条迁移必须进 `test_migrations.py` 的 `BATCH_STEPS` 回归名单
- **前端**：用户页删除入口与确认框、提交列表的提交者显示
- **文档**：`docs/admin-permissions.md`（权限矩阵加一行）、`docs/deployment.md`（健康检查的新行为与 MySQL 复核项）
- **不影响**：nginx 配置（路径未变）、`/api/**` 的 CORS 不对称、沙箱桥接
