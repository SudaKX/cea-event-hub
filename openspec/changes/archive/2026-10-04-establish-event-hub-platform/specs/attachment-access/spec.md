# Spec Delta

## Purpose

让活动提交中上传的私有附件只能被授权方读取，确保任意类型的上传内容都不会被静态暴露或在浏览器中被当作页面执行。

## ADDED Requirements

### Requirement: 数据目录不可静态访问
平台 MUST NOT 以静态资源方式提供活动数据目录。边缘层对该路径前缀 MUST 返回 404，应用层 MUST NOT 挂载该目录。

#### Scenario: 直接请求数据目录路径
- **WHEN** 匿名请求形如 `/data/{event_id}/{file}` 的路径
- **THEN** 响应为 404

#### Scenario: 遍历数据目录被阻止
- **WHEN** 请求中尝试用路径片段逃逸出数据目录
- **THEN** 响应为 404 且不返回任何文件内容

### Requirement: 附件的鉴权访问
附件 MUST 只能通过鉴权端点读取。提交者本人与 `admin` SHALL 可访问；其他已登录用户 MUST 被拒绝；匿名请求 MUST 被拒绝。拒绝时响应 MUST NOT 泄露该附件是否存在。

#### Scenario: 提交者下载自己的附件
- **WHEN** 已登录用户请求自己某条提交中的附件
- **THEN** 响应为该附件的字节内容

#### Scenario: 管理员下载任意附件
- **WHEN** admin 请求任意提交中的附件
- **THEN** 响应为该附件的字节内容

#### Scenario: 其他普通用户被拒绝
- **WHEN** 已登录用户请求他人提交中的附件
- **THEN** 响应为 404，且不透露该附件是否存在

#### Scenario: 匿名请求被拒绝
- **WHEN** 未携带会话的请求访问附件端点
- **THEN** 响应为 401

#### Scenario: 元信息与实际文件不一致时不泄露路径
- **WHEN** 请求的附件标识在数据库中不存在或对应文件已缺失
- **THEN** 响应为 404，且响应中不包含服务器文件系统路径

### Requirement: 附件下载的强制安全响应头
附件下载响应 MUST 携带指示附件下载的 `Content-Disposition`，且 MUST 使用不可被浏览器内联执行的通用二进制类型。平台 MUST NOT 依据上传时客户端声明的类型回显 `Content-Type`。

#### Scenario: 上传的 HTML 被下载而不被执行
- **WHEN** 某提交上传了一个 HTML 文件，随后被下载
- **THEN** 响应类型为通用二进制类型、附带附件下载指示，浏览器不在页面上下文中渲染它

#### Scenario: 客户端声明的类型不影响响应类型
- **WHEN** 上传时客户端声明了一个可执行或可渲染的类型
- **THEN** 下载响应的类型仍为通用二进制类型

#### Scenario: 下载保留原始文件名
- **WHEN** 下载某附件
- **THEN** 响应中的建议文件名与提交时记录的原始文件名一致
