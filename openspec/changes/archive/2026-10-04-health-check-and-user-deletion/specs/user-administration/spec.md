# Spec Delta

## ADDED Requirements

### Requirement: 账号删除
管理员 SHALL 能够彻底删除一个账号。删除 MUST 立即使其会话与未使用的一次性凭据失效，使该用户无法再登录、也没有未完成的找回流程可用。

**删除 MUST NOT 移除该用户提交过的内容。** 那是社团收集的数据，与"这个人还在不在"是两件事 —— 这与既有的"停用不删历史提交"取值一致。删除之后，那些提交的提交者标识 MUST 保持原样，并成为**永久标识**：系统 MUST NOT 让此后注册的任何账号获得同一个标识，否则新账号会从数据角度继承前者的提交与配额计数。

该用户创建的活动与做过的审核 MUST 保留，只是不再归属于任何账号。

守卫与停用同源：MUST NOT 删除最后一个**可用**管理员（角色为 admin **且**已启用），MUST NOT 删除自己。删除 MUST 被记录以便追溯。

#### Scenario: 删除后无法登录
- **WHEN** 某账号被删除后该用户尝试登录
- **THEN** 登录被拒绝

#### Scenario: 删除后既有会话失效
- **WHEN** 某账号被删除而其用户当前已登录
- **THEN** 该用户的后续请求返回 `401`

#### Scenario: 提交保留
- **WHEN** 某账号被删除后管理员查看该用户此前的提交
- **THEN** 提交记录仍然存在，内容与附件完好

#### Scenario: 新账号不继承被删账号的数据
- **WHEN** 删除一个账号，随后有人注册新账号
- **THEN** 新账号的标识与被删账号不同，且它看不到任何前者的提交与配额计数

#### Scenario: 不能删除最后一个可用管理员
- **WHEN** 系统中仅剩一个可用管理员，请求删除该账号
- **THEN** 请求被拒绝并返回 `last_admin_protected`

#### Scenario: 不能删除自己
- **WHEN** 管理员请求删除自己的账号
- **THEN** 请求被拒绝

#### Scenario: 删除不存在的账号
- **WHEN** admin 请求删除一个不存在的用户 id
- **THEN** 响应为 `404`

#### Scenario: 删除被记录
- **WHEN** 某账号被删除
- **THEN** 留有可追溯的记录，说明是谁删除了谁

#### Scenario: 普通用户无权删除
- **WHEN** 已登录的普通用户请求删除任意账号
- **THEN** 响应为 `403`
