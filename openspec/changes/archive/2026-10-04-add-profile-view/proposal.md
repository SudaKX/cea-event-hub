# Proposal

## Why

登录之后普通用户会落在一个**自己进不去的地方**。`LoginView` 在没有 `?redirect=` 时一律跳 `/admin`，而 `/admin` 只对管理员开放 —— 于是一个刚注册的普通成员，登录成功后立刻被挡在门外。

而**非管理员根本没有登出的出口**。整个应用只有 `AdminShell` 里有一个「退出登录」按钮，主页没有、活动页没有 —— 普通用户登录之后就再也退不出来了，只能去清 Cookie。这既说不过去，也让"换个人登录"变成一件需要懂浏览器的事。

规格层面这两件事都无处可依：`web-app-shell` 的"路由结构与保留前缀"只管有哪些路径，没有任何一条规定**登录成功后该去哪**；而"登出"在 11 份规格里**一次都没有出现过** —— 它作为用户可见的能力，从来没有被写下来过。所以这不是"补一个页面"，而是补上一条一直被默认存在的契约。

## What Changes

- 新增**个人中心**视图（路径 `/profile`）：显示当前登录者的身份信息（用户名、显示名、角色、邮箱及其验证状态），并提供**退出登录**按钮。未登录访问它 MUST 被引导到登录页，登录后回到它。
- `profile` 加进**保留前缀清单**。这不是可选项：其余顶层路径一律被解释为活动标识，漏了这一步，`/profile` 会被当成一个叫 profile 的活动 —— 页面能匹配上，但活动页的逻辑会接管它。规格里"静态路径必须同时出现在两处"那句话就是为这类错误写的。
- **登录成功后的默认去向改为 `/profile`**，从 `/admin` 改过来。带 `?redirect=` 时**仍然优先回到原目标** —— 那条既有行为不变（未登录点进管理台 → 登录 → 回到管理台）。
- **首页对已登录用户提供个人中心的入口**。首页目前对已登录者只显示名字与"管理台"（且后者仅管理员可见），普通用户在那里没有任何指向自己的入口。
- **登出不再只存在于管理台**：个人中心提供它，因此任何已登录用户都能结束自己的会话。

## 本期不做

明确排除，避免范围在实现阶段膨胀：

- **改密码**。`api/auth.ts` 里已经导出了 `changePassword`，但没有任何界面调用它；它属于个人中心，但不属于**这一期**。
- **邮箱绑定与重发验证邮件**。`requestEmailVerification` 同样已导出、同样无人调用。个人中心只**显示**邮箱与验证状态，不提供操作。
- **"我的提交"列表**。个人中心不承载历史记录。
- **编辑资料**（改显示名等）。本期没有写操作，个人中心是只读的。
- **账号自助删除**。删除仍只由管理员执行（见 user-administration）。
- **会话管理**（列出其他设备并逐个踢掉）。
- **头像与任何上传**。
- **注册成功后的去向**不变：仍走邮箱验证流程，不直接进个人中心。
- **注册这条岔路上的回跳目标会丢**（**已向用户报备并获明确接受**，不是遗漏）：守卫把 `?redirect=` 交给登录页，但登录页的「注册新账号」与核销页的「去登录」都没有把它带过去，于是"点进受保护页面 → 改去注册 → 验证邮箱 → 去登录"这条路上，原目标丢失，最终落到个人中心。之所以不在本期一并解决：验证链接是**后端**发到邮箱里的，`?redirect=` 要穿过"离开站点去收信"这一步，靠 URL 传不过去 —— 要么把它持久化到本地存储（引入一份跨会话状态与它的清理规则），要么让后端在发信时记住目标。两条都不是一行改动，值得单独一期。本期的登录路径（直接登录、被守卫引到登录页后登录）行为正确。

## Capabilities

### New Capabilities

（无。个人中心不构成一个新能力：它是"应用外壳"的一部分 —— 路由、入口与导航，正是 `web-app-shell` 覆盖的范围。）

### Modified Capabilities

- `web-app-shell`：
  - 「路由结构与保留前缀」—— 保留前缀清单加入 `profile`，并新增 `/profile` 这一路由。
  - 「平台首页」—— 已登录访问者 MUST 能从这里进入个人中心。
  - 新增「登录成功后的去向」—— 无 `?redirect=` 时进个人中心；有则回到原目标。
- `identity-auth`：
  - 新增「主动登出」—— 任何已登录用户 MUST 能在界面上结束自己的会话；登出后服务端会话失效、界面回到未登录态。这一条此前完全缺失。

## Impact

- **前端**：`views/profile/ProfileView.vue`（新）、`router/index.ts`、`views/HomeView.vue`、`views/auth/LoginView.vue`、`api/auth.ts`（复用已有的 `logout`）；`AdminShell` 里那个登出按钮的归属需要一并理顺 —— 两个地方各写一遍登出逻辑，正是刚归档那次变更里"同一份渲染写两遍就漏一处"的同一个形状。
- **后端**：**无改动**。`GET /auth/me` 与 `POST /auth/logout` 都已存在并被测试覆盖，本期不新增接口、不改契约。
- **规格**：`web-app-shell`、`identity-auth` 各一份 delta。
- **文档**：`docs/` 里若有描述登录后去向或登出入口之处需同步。
- **测试**：路由与保留前缀两侧都要有断言（漏掉保留前缀时 `/profile` 会被当成活动标识，而那不会报错）；登录默认去向；首页入口；登出后回到未登录态。
