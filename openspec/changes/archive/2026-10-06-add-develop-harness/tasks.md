## 7. 拦截改为"挂起 → 选择"，面板改为工具轨分页

> 这一组替换第 4 组里的拦截模型。原模型是"抢先应答"：请求照常发出去，面板抢先回一条伪造结果。
> 它做不到"看清请求内容再决定"，"转发"也不成为一个选择（请求早就发出去了）。改动理由与代价
> 见 design.md 决策 11 / 12。

- [x] 7.1 宿主增加挂起口子（`shouldHold` / `onHold`）与结算入口（`forwardHeld` / `failHeld`）；挂起的请求不进网络、也不进超时。验证：`vitest` 断言转发时后端接口被调用、假响应时一次都没被调用
- [x] 7.2 调试台提供拦截请求的**多选过滤**，命中后挂起并展示请求内容（操作名、请求 id、完整参数）。验证：只勾一个操作时另一个操作照常放行；挂起条目里能看到参数内容
- [x] 7.3 每条挂起的请求可分别选择**假响应**或**转发**；转发返回后端真实值，假响应不产生任何后端请求。验证：两条路径各自的断言，且把假响应改成偷偷转发后对应用例失败
- [x] 7.4 提供**可开关的默认应答**（默认关闭），开启后命中请求按所选动作直接结算、不进队列。验证：开启后不必逐条点且队列为空；关闭时一律挂起
- [x] 7.5 面板改为**工具轨 + 分页**（状态 / 身份 / 动作 / 拦截 / 日志），工具轨放在**最右侧**（`iframe | 内容 | 轨`，分隔线与选中指示一并镜像）；只有日志与挂起队列这两处流式内容自己滚动；拦截页在轨上带挂起数角标。验证：五页可切换且各自只显示自己的内容；挂起一条后角标出现
- [x] 7.6 钉住"生产宿主不传行为口子"：验证：`sandbox.spec` 断言 `EventView` 不含 `shouldHold` / `onHold`，且往它里面加一句后该断言失败
- [x] 7.7 同步 `docs/dev-harness.md` 与规格：拦截章节改写为挂起模型，说明"为什么必须是挂起"、代价（宿主上多了行为口子）与唯一的安全条件（生产宿主不传它）。验证：文档描述与实测一致，且 `openspec validate --strict` 通过
