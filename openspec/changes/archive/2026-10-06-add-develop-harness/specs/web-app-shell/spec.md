# Spec Delta

## MODIFIED Requirements

### Requirement: 路由结构与保留前缀
单页应用 MUST 保留 `admin`、`login`、`register`、`reset`、`verify-email`、`verify-registration`、`profile`、`api`、`content`、`data`、`assets`、`sdk`、`draft`、`develop` 作为内部前缀。根路径 `/` MUST 作为平台首页（见下一条），除此以外的非保留顶层路径 MUST 被解释为活动标识并导航到活动页。无法匹配到已发布活动的标识 MUST 显示未找到页面。服务端 MUST 对未知路径回退到应用入口以支持前端路由。

平台自身的静态路径（如验证落地页）MUST 同时出现在**路由表**与**保留前缀清单**两处：前者让它可被匹配，后者让它在"其余顶层路径都是活动"这条规则里被排除。二者缺一，那一页都会被当作活动标识。

保留前缀清单 MUST 覆盖平台实际占用的全部顶层前缀，包括那些由服务端而非前端路由处理的路径。`draft` 属于后者：它在开发模式下由服务端提供草稿活动内容，前端路由不注册它，但它同样不能被解释成活动标识。

`develop` 是调试台路径，只在开发构建的路由表中存在。保留前缀清单是构建期常量、不随构建模式变化，因此它在两种构建中都保留 `develop` —— 让清单随构建模式变化，会使"哪些标识不能用作活动"在不同构建下不一致，而这是比多让出一个标识名更坏的取舍。

#### Scenario: 进入管理台
- **WHEN** 访问 `/admin` 路径
- **THEN** 进入管理台界面而非活动页

#### Scenario: 进入个人中心
- **WHEN** 访问 `/profile` 路径
- **THEN** 进入个人中心界面，而不是把它当作标识为 `profile` 的活动

#### Scenario: 个人中心路径出现在两处
- **WHEN** 检视路由表与保留前缀清单
- **THEN** `profile` 同时出现在两处 —— 只出现在路由表时它会被活动页逻辑接管，且不报任何错

#### Scenario: 开发构建中调试台路径出现在两处
- **WHEN** 在开发构建中检视路由表与保留前缀清单
- **THEN** `develop` 同时出现在两处；生产构建中它只出现在保留前缀清单里

#### Scenario: 草稿前缀不被当作活动
- **WHEN** 访问 `/draft/{name}/index.html`
- **THEN** 由服务端提供草稿内容，而不是把它当作标识为 `draft` 的活动

#### Scenario: 根路径是首页
- **WHEN** 访问 `/`
- **THEN** 显示平台首页，而不是重定向到管理台

#### Scenario: 顶层路径解释为活动
- **WHEN** 访问一个已发布活动的标识
- **THEN** 进入该活动的活动页

#### Scenario: 未知活动显示未找到
- **WHEN** 访问一个不存在或未发布的活动标识
- **THEN** 显示未找到页面

#### Scenario: 保留前缀不会被当作活动
- **WHEN** 访问 `/login` 或 `/assets/...`
- **THEN** 不会尝试将其作为活动标识解析

#### Scenario: 静态路径赢过活动路由
- **WHEN** 访问 `/verify-registration?token=...`（一个形如活动标识的单段路径）
- **THEN** 进入注册核销页，而不是活动页或未找到页

#### Scenario: 直接访问深层路径可正常加载
- **WHEN** 直接在浏览器中打开一个管理台深层路径
- **THEN** 服务端返回应用入口，前端路由正确还原该页面
