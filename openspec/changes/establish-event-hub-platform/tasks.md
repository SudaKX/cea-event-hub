- [x] 8.8 实现 janitor 后台任务：回收超时未完成的落盘记录及其文件、清理过期会话与令牌、清理限流键；以测试断言残留记录被回收后不再长期占用配额、过期数据被清除为验证
- [x] 8.9 在 `docs/` 记录提交契约（两端点形状、`kind` 规则、幂等语义、错误码表）；以文档中的错误码与实现返回的 `code` 逐一对应为验证
- [x] 8.10 实现单个提交者的份数上限（`max_per_submitter`，为空不限）：计数由 `submitter_quotas` 表上的**单语句 CAS** 维护，**而不是"数一下再插"** —— 后者在 SQLite 上会撞快照冲突、在 MySQL 的可重复读下两个并发请求各自数到 0 然后双双插入，**静默超限**；计数无论是否设上限都维护（此后才设上限时不必回填），删除时退还，超限返回 `409 submitter_quota_exhausted`（**与活动满额的 `quota_exhausted` 分开** —— "活动没位置了"与"你不能再交了、别人还可以"可采取的行动完全不同）；迁移按既有提交回填，不回填的话设了上限也挡不住早已超额的人；同时明确记录这条限制**对匿名提交只是建议性的**（标识来自客户端自报的 `client_id`，换浏览器即绕过，要真正限制需活动要求登录）并在管理界面写明；以测试覆盖上限生效、他人不受影响、删除退还、幂等重放不重复计数、回填后立即生效，以及变异验证（去掉 CAS、去掉退还、去掉回填各自都会让测试失败）为验证
